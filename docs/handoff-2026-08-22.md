## The terminal input layer

pi requests Kitty keyboard protocol flags 7: 1 disambiguate, 2 report event
types, 4 alternate keys. Every consequence below follows from that number.

**Flag 2 means every press has a matching release.** This is the single most
expensive fact in the whole session. A release of `s` arrives as
`\x1b[115;1:3u`: the modifier field has been dropped, so a naive parser reads
it as a plain `s` and completes a chord the user only pressed the prefix of.
That was the "ctrl+s stashes and the prompt disappears immediately" bug, and
the user diagnosed it before I did. `chord.ts` now drops releases first:

```ts
export function isKeyRelease(data: string): boolean {
	if (data.includes("\x1b[200~")) return false;   // a paste can contain ":3F"
	return /:3[u~ABCDHF]/.test(data);
}
```

The terminator set matches pi-tui's own `isKeyRelease`. It is duplicated rather
than imported because pi injects `@earendil-works/pi-tui` as a jiti virtual
module: the import resolves when pi loads the file and fails under `bun test`.
Any matcher this extension needs has to be reimplemented locally, and
`pi-contract.test.ts` exists to catch it drifting.

**Functional keys lose their legacy encoding; text keys keep theirs.** Up is
`\x1b[1;1:1A`, not `\x1b[A`. `s` is still `s` on press. This asymmetry hid a
bug for months: the stash list's key table matched literal `\x1b[A`, so arrow
keys had never worked in any build, and nobody noticed because `j`/`k` did.

**CSI-u shape**, as `chord.ts` parses it:

```
CSI unicode-key ":" shifted-key ":" base-layout ";" modifiers ":" event-type u
```

The modifier field is 1-based, so subtract one; 1=shift, 2=alt, 4=ctrl. Caps
Lock and Num Lock ride along in the same field as 64 and 128 and must be masked
off, or a chord silently stops working with Caps Lock on. The second field is
the shifted codepoint: `\x1b[117:85;2u` is shift+u reporting both `u` and `U`.
Without reading it, `U` (unstash all) cannot exist as a binding at all.

**ctrl+? cannot be told from ctrl+/.** A legacy terminal cannot report shift on
a control character, so both are `0x1f`. `matchesCtrlQuestion` accepts the bare
`0x1f` and, when a CSI-u form arrives, checks the shifted codepoint for `?`.

## pi's drawing surfaces

Three ways to put something on screen, with different anchors. Choosing wrong
produced four separate visual bugs.

| Surface | Anchored to | Focus | Cap |
| --- | --- | --- | --- |
| `setWidget(key, lines, {placement})` | the editor, above or below it | none | `MAX_WIDGET_LINES = 10`, silent |
| `ctx.ui.custom({overlay: true})` | the **terminal**, not the conversation | none | grows the drawn region |
| `ctx.ui.custom({overlay: false})` | swaps into the **editor's** container | yes | replaces the prompt |

Three things follow.

`overlay: true` has no anchor meaning "where the conversation ends".
`compositeOverlays` computes `minLinesNeeded = max(lines, row + overlayHeight)`,
and `center` resolves `row` against terminal height, so a centred overlay padded
the transcript with twenty blank rows. `bottom-left` put the menu on the
terminal floor, under the prompt. The only surface that lands at the end of the
chat log is a widget with `placement: "aboveEditor"`. All three pi-extras
surfaces now use it: `pi-extras:chord`, `pi-extras:stash`,
`pi-extras:shortcuts`.

`overlay: false` ate the prompt, because the non-overlay branch swaps the
component into the editor's own container. That is what "why tf does the stash
list replace the chat box" was.

`MAX_WIDGET_LINES = 10` truncates without telling the extension, leaving only
`... (widget truncated)`. Reproduced deliberately: a full ten-entry stash plus a
title plus a help line is twelve rows, so the last entry, the help line, and
every key it named vanished. `overlay.ts` now derives its budget from the cap
rather than guessing:

```ts
export const MAX_HELP_ROWS = 2;
export const VISIBLE_ROWS = 10 - 1 - MAX_HELP_ROWS - 1;   // = 6
```

Also: `SizeValue` is `number | "N%"`. `width: "auto"` is ignored, not honoured.

## Input listener priority

`TUI.handleTerminalInput` consults `inputListeners` **before** the focused
component. That is the whole reason a chord is possible without replacing pi's
editor: `registerShortcut` takes a single `KeyId` and `KeybindingsManager`
resolves one key to one action, so neither can express "ctrl+g, then s".

Within the extension the order is shortcuts panel, then list, then chord, and
ctrl+c is deliberately absent from both key tables so the caller can dismiss
the surface and pass the byte on to interrupt:

```ts
if (this.shortcutsOpen) {
    this.closeShortcuts();
    return matchesCtrl(data, "c") ? undefined : { consume: true };
}
```

## The key map as it ended up

```
ctrl+s     stash the prompt, or bring the last one back
           (decided by whether there is a prompt)
ctrl+g     prompt stash menu
             s stash · u unstash · U unstash all · l list · c copy · x cut · esc cancel
ctrl+?     the shortcuts panel, plus a pointer to /hotkeys
ctrl+c     dismisses any surface and still interrupts
/stash     the list
list:      enter restore · c copy · d delete · D clear all · / filter · esc close
```

`CHORD_TIMEOUT_MS` is 5000. It was 1500, which is under the time it takes to
remember which letter you wanted: press the prefix, pause to think, and the `s`
lands in the prompt instead. Measured against the real TUI, the same two
keystrokes open the stash at a 1.2s gap and type an `s` at 2.0s.

## Permissions

The operator constraint, in the user's words: "I dont want a bunch of rules
that hard deny, i want to rely on the auto classifier."

That collides with ADR 0007 §5. `delegation-envelope.ts` caps any link's
`allow` to `defer` on an excluded surface, and upstream hardcodes that set as
`["external_directory", "path"]`. So every `/nix/store` read fell through to a
prompt no matter what the classifier said. `packages/extensions/
gotgenes-pi-permission-system-patches.nix` makes the set configurable, keeping
upstream's literal as the fallback, so a typo can only fail to narrow the
checkpoint, never disable it. `dotfiles` then sets
`permissionSystem.delegationExcludedSurfaces = [ "path" ]` when jailed, which
reaches the extension as `PI_PERMISSION_DELEGATION_EXCLUDED_SURFACES`.

Separately: **a trailing `*` never matches the bare directory.** The
extension's own schema says so. `"/nix/store/*" = "allow"` leaves `/nix/store`
itself prompting. Every directory has to be named twice.

## Jail

`FFF init failed: ... Resource temporarily unavailable (os error 11)` blocked
startup entirely whenever a second session opened. `/proc/locks` showed
`POSIX ADVISORY WRITE ... 2 2`. `mdb_reader_pid` takes an fcntl write lock on
the byte at offset `pid` in `lock.mdb`, and `--unshare-pid` makes every jailed
pi pid 2 inside its own namespace, so two sessions collide on byte 2 and the
second gets EAGAIN. IXON, Bun's `\x13` delivery, and bwrap itself were all
excluded before that landed.

The fix is `jail.privateAgentSubdirs`, a per-session tmpfs over the named
subdirectory. It costs whatever persistence that path held.

**bwrap applies mounts in order**, so in `coding-agent/options.nix` the tmpfs
permission has to come *after* `configPermission`, or the config bind lands on
top of it.

## Statusline

`AGENT_STATUSLINE_CONFIG` was exported by pi-nix and read by nothing:
`ResolvePath` knew only the Claude names, and the jail does not bind
`~/.claude`, so `Load()` silently returned `Defaults()` and drew ten-cell bars
nobody configured. The fix was a test checked against the old value first.

Row layout ended at `Row3: {"autoMode", "cache"}`, `Row4: nil`. The cache row
is an icon and a percent; the `35/41` figure was dropped because it counts
requests that hit the cache at all, which is not the number anyone wants.

## Wrong turns

Recorded because each looked correct from the source.

**"pi never receives ctrl+s."** I said this and built a question around it.
Two compounding errors: the probe used a 2-second gap, longer than the
then-1500ms timeout, so the chord had already expired; and the probe extension
registered *after* pi-extras, which consumed the keys first. pi receives ctrl+s
fine.

**"The statusline tick is blanking the widget."** I claimed agent-statusline's
1Hz tick blanked a shared `belowEditor` container, and rebuilt the feature as
an overlay around that inference. I never reproduced the blanking. The real
cause was the key-release bug above. The overlay detour is what produced the
padding and prompt-eating bugs.

**An accidental push.** A `git commit -am` on a lock bump swept the user's
unverified Darwin sandbox work into `8882727` under a message mentioning only
the bump. Disclosed rather than rewritten, since two locks already referenced
it; `sandbox.enable` now carries a `NOT VERIFIED` paragraph in its own option
doc.

**`${src}` inside a `''` block** in `sync-upstream.nix`. Nix interpolated what
I had written as a comment, breaking `nix flake check` after the IFD rewrite,
and I had pushed it without running the check. Escape as `''${src}`.

**Untracked files are invisible to the flake.** `hint.ts` and `shortcuts.ts`
each produced `Cannot find module` until `git add -N`.

## The recurring failure mode

Configuration that reads as intent and does nothing. Every one of these was
invisible to a green build and caught only by inspecting a rendered artifact or
a built store path:

- an inert `delegateToPermissionSystem`
- an empty `extensionPackages`
- an unreachable `nix` allow rule
- a dropped `protectedPaths`
- an unread `AGENT_STATUSLINE_CONFIG`
- a fork pin one commit behind the fix it was pinned for
- `width: "auto"`
- a dead `ctx.ui.custom` declaration with no caller

The check that catches this class is to grep the **built store path**, not the
source. That is how the stale `v1.11.0-jg.2` pin was found: the suppression
commit was `d2846b5`, one past the tag, and `pi-automode:status` was still in
the closure.

## Verification that worked

Driving the real pi TUI through a pty with `pyte` reconstructing the screen.
Where the screen could lie, a stale region kept showing a cleared prompt, assert
against the **stash file on disk** instead: `[] -> ['quick draft'] -> []`.

For the extension forks, `--replace-fail` in `patchPhaseExtra` is the house
pattern: an upstream move breaks the build instead of silently reverting the
patch.
